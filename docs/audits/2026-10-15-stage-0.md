## Audit coverage

| Area | Required review and evidence |
| --- | --- |
| Privileged execution | Command arguments and input validation; generated shell quoting; file paths, ownership, permissions, partial writes and error propagation. Review installer and updater recovery as well as backend IPC. |
| State changes and rollback | Inventory every sysctl, qdisc, sysfs/module write, service change, dispatcher and NM profile field. Establish the intended restoration contract and interaction with pre-existing configuration. |
| Connection lifecycle | Boot, disconnected operation, reconnect failures, switching saved profiles, suspend/resume, reset/uninstall, backend changes and interruption during updates. |
| Optimization value | For power save, ASPM/runtime PM, BSSID, band, DNS, IPv6, buffers and CAKE: document the original problem, current-system relevance, tradeoffs and measured result. |
| Concurrency and responsiveness | Synchronous subprocesses in async methods, timeouts, overlapping settings/update/reapply calls, frontend busy handling and background lifecycle cleanup. |
| Platform compatibility | Actual NetworkManager/backend/driver state, supported paths and helpers, kernel capability detection, SteamOS Stable changes and separately tracked Beta changes. |
| Diagnostics and UI | Read side effects, stale/error/unknown states, misleading success reports, visibility of disconnection and accuracy of support/performance claims. |
| Verification | Add isolated regression tests for confirmed fixes; run the existing delivery checks. Execute actual network/system changes only on the agreed Linux test device with the recorded recovery procedure. |

Each finding must record the reviewed commit and file/line, trigger, impact, evidence, severity, fix or disposition, and recheck result. Distinguish confirmed code behavior, a reproducible defect, an untested hypothesis and an accepted limitation. Do not refactor unrelated code merely because it is inherited.
