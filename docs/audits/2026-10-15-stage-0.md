The [initial owner report](../testing/results/2026-10-15-owner-inventory.md) distinguishes that subjective observation from controlled results. Do not treat the device as an untouched baseline or substitute published versions for installed evidence.

The primary release-validation target is LCD / Stable. Stay on Stable for baseline testing. OLED, other handhelds, other distributions and Beta/Preview have no recorded runtime-validation results in this fork. Preserve their existing implementation while qualifying support claims to match evidence.

## Audit coverage

| Area | Required review and evidence |
| --- | --- |
| Privileged execution | Command arguments and input validation; generated shell quoting; file paths, ownership, permissions, partial writes and error propagation. Review installer and updater recovery as well as backend IPC. |
| State changes and rollback | Inventory every sysctl, qdisc, sysfs/module write, service change, dispatcher and NM profile field. Establish the intended restoration contract and interaction with pre-existing configuration. |
| Connection lifecycle | Boot, disconnected operation, reconnect failures, switching saved profiles, suspend/resume, reset/uninstall, backend changes and interruption during updates. |
| Optimization value | For power save, ASPM/runtime PM, BSSID, band, DNS, IPv6, buffers and CAKE: document the original problem, current-system relevance, tradeoffs and measured result. |
| Concurrency and responsiveness | Synchronous subprocesses in async methods, timeouts, overlapping settings/update/reapply calls, frontend busy handling and background lifecycle cleanup. |
| Platform compatibility | Actual NetworkManager/backend/driver state, supported paths and helpers, kernel capability detection, SteamOS Stable changes and separately tracked Beta changes. |
| Diagnostics and UI | Read side effects, stale/error/unknown states, misleading success reports, visibility of disconnection and accuracy of support/performance claims. |
| Verification | Add isolated regression tests for confirmed fixes; run the existing delivery checks. Execute actual network/system changes only on the agreed Linux test device with the recorded recovery procedure. |

Each finding must record the reviewed commit and file/line, trigger, impact, evidence, severity, fix or disposition, and recheck result. Distinguish confirmed code behavior, a reproducible defect, an untested hypothesis and an accepted limitation. Do not refactor unrelated code merely because it is inherited.

## Initial observations (historical entry; dispositions now in the report)

These observations are supported by static inspection of the baseline; their existence is not a completed severity assessment or proof of a device regression.

| Observation | Evidence at baseline | Audit question |
| --- | --- | --- |
| Reset/disable/uninstall use fixed sysctl values and queue defaults. ASPM/runtime PM restoration also writes assumed values rather than reading a pre-change snapshot. | `main.py`: `SYSCTL_DEFAULTS`, `_apply_pcie_aspm_fix`, `_uninstall`, `set_buffer_tuning`, `reset_settings` | Are these values appropriate for the actual OS and pre-existing configuration? What should the supported rollback contract be? |
| A status request can save settings, raise autoconnect priority and repair profile settings. | `main.py`: `get_status` | Separate observation from mutation before reusing status logic for continuous monitoring. Check failure/reporting behavior of existing repairs. |

| Backend detection uses specific helper/config paths and service checks. | `main.py`: backend constants, `_get_backend_method`, `_get_current_backend`, backend switching methods | Match the effective NetworkManager configuration and currently running backend; check compatibility aliases and interrupted switching. |

| [SteamOS 3.9.2 — Beta/Preview, 2026-09-25](https://steamcommunity.com/games/1675200/announcements/detail/674006995886409303) | Cumulative 3.9 notes describe wpa_supplicant as the default for new installations, faster wpa_supplicant resume, and existing installations retaining iwd unless changed. The newest Stable and Beta entries found in the queried official feed were 3.8.28 and 3.9.2 respectively. This is a dated research snapshot, not an installed-version report or a permanent statement of the latest release. A changelog establishes the vendor's reported change; code review and device tests establish whether our implementation still needs a workaround.
