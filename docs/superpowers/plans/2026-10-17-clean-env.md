# clean_env default Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Systemic `LD_LIBRARY_PATH` stripping for all plugin-spawned system binaries (S-BE-06 mechanism fix).

**Architecture:** Flip `_run_cmd` default to `clean_env=True`; audit all 61 call sites; mechanism + static tests; docs gotcha update. No frontend, no `dist`, no IPC changes.

**Tech Stack:** Python `main.py`, `unittest` isolated fixtures on Windows, Git Bash on PATH.

**Spec:** `docs/superpowers/specs/2026-10-17-clean-env-design.md`

## Global Constraints

- Windows: isolated fixtures only; never import the real root plugin; never execute real setters/lifecycle/switchers. AST-extract + fail-closed builtins; `subprocess.run` mocked (never spawned).
- Git Bash on PATH (`bash --version` works).
- No `connection.autoconnect-priority 100` writes; snapshot/owner/reconnect/backend semantics unchanged.
- No new IPC methods/signatures; no frontend changes; no `dist` rebuild expected (verify empty `dist/` diff).
- No version bump, no Stable/beta, no Watchdog, no DNS work, no service-state restoration.

## Review Focus

- A poisoned parent env must never reach a system binary by default — expect stripped env in the captured kwarg.
- An explicit opt-out must be justified or absent — expect zero `False` or a listed addendum.
- Every call site must be classified — expect the 61-row audit disposition, especially helper/modprobe/restart paths.
