# AGENTS.md — WiFi Optimizer (Decky Loader plugin)

Decky plugin (Steam Deck / handhelds): React TS frontend + Python backend (runs as **root** in `plugin_loader`) + NetworkManager dispatcher script for wake/reconnect persistence.

## Commands

- `pnpm i` / `pnpm run build` (`rollup -c` via `@decky/rollup`). Requires Node + **pnpm v9**. No test, lint, or typecheck scripts.
- If the global pnpm version differs, use `npm exec --yes --package=pnpm@9 -- pnpm install --frozen-lockfile` and `npm exec --yes --package=pnpm@9 -- pnpm run build`; do not upgrade the lockfile or global pnpm just to build this project.
- `tsconfig.json` enables `strict`, `noUnusedLocals`, and `noUnusedParameters`; keep sources free of unused variables/parameters. The Rollup build does not replace a standalone type check.
- To check project types, use `npm exec --yes --package=pnpm@9 -- pnpm exec tsc --noEmit --skipLibCheck`. A full `tsc --noEmit` currently reports TS2307 in `@decky/api` 1.1.3 for missing `react-router` declarations, including on the unchanged baseline. `--skipLibCheck` skips dependency declaration checking; do not change dependencies or relax `tsconfig.json` just to silence this dependency issue.
- Deploy: copy `.vscode/defsettings.json` → `.vscode/settings.json` (gitignored, fill Deck IP/pass), then VS Code `builddeploy` task (build → rsync → `ssh … 'sudo systemctl restart plugin_loader'`). Manual on-Deck install/update uses `install.sh`; in-app updates use a detached shell script generated by `apply_update()` in `main.py`. Both copy `plugin.json`, `package.json`, `main.py`, `decky.pyi`, `dist/index.js`, optional `dist/index.js.map`, and `defaults/dispatcher.sh.tmpl`. The installer replaces the plugin directory and creates `py_modules/.keep`; settings live outside that directory.
- Always rebuild (`pnpm run build`) before deploy/install; `dist/index.js` is the shipped bundle.

## Architecture

- `src/index.tsx` — single `Content()` panel; `src/backend.ts` — `callable<>()` wrappers; names must **exactly match** `async` methods on `Plugin` in `main.py` (Decky IPC).
- The plugin-level Steam app lifetime listener calls `reapply_volatile()` 3 seconds after an app starts, including when the panel is closed. Keep that method free of WiFi reconnects and unregister the listener on dismount.
- `main.py` — all system changes. Settings in `settings.json` under `DECKY_PLUGIN_SETTINGS_DIR`, merged against `DEFAULT_SETTINGS` (stale keys stripped), written atomically via `.tmp` + `os.replace`, with `last_applied` timestamp.
- `defaults/dispatcher.sh.tmpl` — placeholders `__SETTINGS_PATH__` / `__PLUGIN_DIR__` substituted at install to `/etc/NetworkManager/dispatcher.d/99-wifi-optimizer` (chmod 755). Reapplies volatile state (power save, PCIe ASPM, buffers, CAKE) on every WiFi `up`, independent of Decky; self-deletes if plugin dir is gone.
- Per-connection (NM profile, survives reboot, needs forget/rejoin to clear): BSSID lock, band, DNS, IPv6, `autoconnect-priority 100`. System-wide/volatile (reset on reboot, restored by dispatcher or `_main`): `iw power_save`, PCIe ASPM, sysctl buffers, CAKE.
- WiFi backend choice is system-wide. Current reset/uninstall code and dispatcher self-removal delete `GENERIC_BACKEND_CONF` (`/etc/NetworkManager/conf.d/99-wifi-optimizer-backend.conf`). They leave the SteamOS helper configuration (`99-valve-wifi-backend.conf`) and systemd backend service state in place; do not assume reset/uninstall preserves the generic override or fully restores a previous backend.

## Gotchas

- Backend shell-outs use absolute paths (`/usr/bin/nmcli`, `/usr/bin/iw`, `/usr/bin/sysctl`, …). `main.py` has a `decky` fallback to `/tmp/wifi-optimizer` for off-Deck static analysis. Do not call setters or lifecycle hooks on Windows: some write files even if Linux tools are unavailable. Use static checks locally and verify actual WiFi behavior on a supported Linux device.
- `get_status()` has side effects: it saves the last connection UUID, raises its autoconnect priority, and repairs drifted IPv6/band profile values. Do not treat it as a strictly read-only diagnostic call.
- Pass `clean_env=True` to `_run_cmd` for `curl`/`bash` children: strips `LD_LIBRARY_PATH` so they use system libs instead of Decky's PyInstaller-bundled ones (avoids OpenSSL/readline symbol errors).
- Apply order matters (`_main`): buffer tuning (`txqueuelen 2000`) → CAKE (overrides `txqueuelen` to `256`) → power save last. Uninstall restores `txqueuelen 1000` + `SYSCTL_DEFAULTS`. Keep `SYSCTL_PARAMS`, driver sysfs paths, and the dispatcher template in sync when changing values.
- Enablers requiring live BSSID need active WiFi (`_require_wifi`); disablers should use `_resolve_uuid()` so they work on saved profiles while disconnected.
- Any NM profile change that reconnects must call `_hard_reconnect(uuid)` (`radio wifi off/on` + `con up`); frontend waits `RECONNECT_DELAY` (4s) before refresh.
- Frontend: `busyRef` + `isBusy` re-entrancy guard; always `await refreshStatus(true)` (forced) **before** clearing busy to avoid stale-toggle flash. Interval refresh (3s) and update heartbeat (5min) pause when `document.hidden`. Update checks dedupe within 60s; update apply has a 60s safety timeout. `getBadge()` shows only `failed`/`drifted`, never binary on/off.
- `pnpm.peerDependencyRules.ignoreMissing: [react, react-dom]` is intentional (provided by Decky) — do not add them as deps.
